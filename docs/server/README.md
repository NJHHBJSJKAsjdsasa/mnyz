## 3. 分册深度标准（每篇必须满足）

一篇「详细设计」至少包含以下 8 项，缺一不算完成：

| # | 要素 | 具体到什么程度 |
|---|---|---|
| 1 | 字段级/参数级说明 | 表 → 列 → 类型 → 约束 → 含义；公式 → 常数 → 取整方式 |
| 2 | 状态机 / 时序 | 状态、触发条件、时间参数、超时、幂等键、补偿动作 |
| 3 | 契约 | 函数/接口的输入、输出、错误码；失败返回什么 |
| 4 | 边界与失败矩阵 | 空值、上限、并发、依赖不可用时的行为 |
| 5 | 数值算例 | 给定一组输入算出唯一结果（可当测试期望值） |
| 6 | 测试用例 | 可执行断言（T1…Tn），不是「需要测试」 |
| 7 | 验收清单 | 可勾选的客观条件 |
| 8 | 交叉引用 | 相关分册链接，避免单边修改 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| 玩家（player） | 一个账号在一个宇宙里的角色；聚合根，所有写操作先锁它 |
| 宇宙（universe） | 由 `seed + cosmic_origin_time` 确定的星系集合 |
| 基础行星（base） | 由 seed 生成、可完全重建的行星数据（缓存） |
| 改造层（delta） | 玩家留下的、不可重建的行星修正（玩家数据） |
| 世界层（world） | 共享行星的唯一真相（`world_planets`） |
| 账本（ledger） | 双分录、只追加的资金流水，余额由它派生 |
| 物化余额（wallet） | `wallets.balance`，账本的缓存值，每事务同步更新 |
| 幂等键 | 客户端生成的 UUID，服务端 24h 内去重 |
| outbox | 与业务同事务写入的事件表，由 worker 外发 |
| 分片（shard） | 按 `sector` 把行星写到固定区域 |
| 区域（region） | 独立部署单元，含自己的 PG/Redis/服务实例 |

## 5. 维护纪律

1. 改数值/表结构时，**先改分册，再改代码**；主文档只同步结论。
2. 每个分册末尾都有「验收清单」，PR 描述必须引用对应条目。
3. 任何跨分册的决策（例如「行星归属是否影响账本」）必须在两个分册里都留链接，避免单边修改。
4. 本目录不写业务实现代码；DDL 属于数据库设计产物，集中在 [19-ddl.md](19-ddl.md)。
