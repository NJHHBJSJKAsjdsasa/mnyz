# 01 · 目标环境、SLO 与容量（详细设计）

> 对应主文档 §0、§1。本篇给出：环境与凭据、v1 被否的具体后果、SLO 指标与测量口径、容量推导（含公式）、成本、降级目标、验收。

---

## 1. 环境

| 项 | 值 | 说明 |
|---|---|---|
| DB | PostgreSQL 15 | 主 + 同区同步副本 + 跨区异步副本 |
| 开发 DSN | `postgresql://postgres:123456@127.0.0.1:5432/atlas` | 仅本机 |
| 生产 DSN | pgbouncer 6432 | 应用不直连 5432 |
| 应用 | Flask 3.1.3 + Gunicorn/Uvicorn | 无状态 |
| Redis | 7.x | 限流/缓存/锁/队列 |
| 任务 | Celery worker + beat | 独立进程 |
| 入口 | Nginx | TLS/HTTP2/静态/反代 |

### 1.1 凭据纪律（可执行）

1. `.env` 在 `.gitignore`；仓库只提交 `.env.example`（值为占位符）。
2. 启动时若 `ATLAS_DATABASE_URL` 含 `postgres:` 且 `ATLAS_ENV=prod` → **拒绝启动**（生产必须独立角色）。
3. 提交前自查：`git diff --cached | findstr /i "123456"` 必须为空。
4. 日志与错误页统一打码：密码、token、完整邮箱。

## 2. v1 被否的具体后果（写给评审）

| 错误 | 可观测后果 |
|---|---|
| 匿名令牌 | 玩家清缓存即失联；无法封禁；客服无法定位同一人 |
| 每域大 `jsonb` | 无法按字段查询/排行；并发写覆盖；schema 漂移 |
| 可变余额 | 无审计；一次并发写就能造钱且查不出 |
| 请求内结算 | 长事务、P99 抖动；多实例重复结算 |
| 内存限流 | 4 worker 下实际阈值 ×4；多实例失效 |
| 无后台任务 | 行情/过期/清理依赖访问，漏算堆积 |
| localStorage 可写 | 改存储即可改数值 |
| 手写迁移 | 无回滚；多人分支冲突 |
| 无 SLO | 无法判断能否上线 |

## 3. SLO 与测量

| 指标 | 目标 | 测量口径 | 告警 |
|---|---|---|---|
| 可用性 | 99.9%/月 | 非 2xx/3xx 且非 4xx 客户端错误的请求 / 总请求 | 5 分钟窗口错误率 > 0.5% |
| 延迟 p50 | < 40ms | histogram `atlas_http_request_duration_seconds` | — |
| 延迟 p95 | < 120ms | 同上，排除 `/health/*` | 10 分钟 > 200ms |
| 延迟 p99 | < 300ms | 同上 | 10 分钟 > 500ms |
| 写 p95 | < 200ms | 按 method != GET | 同上 |
| 5xx 率 | < 0.1% | 同上 | 5 分钟 > 0.5% |
| 账本对账 | 偏差 0 | 每小时任务 | 任意偏差 P1 |
| RPO | ≤ 5 分钟 | WAL 归档延迟 | > 5 分钟 |
| RTO | ≤ 30 分钟 | 季度演练实测 | 演练超标 |

错误预算：月 99.9% → 约 43 分钟不可用；消耗 > 50% 时冻结非必要发布。

## 4. 容量推导

### 4.1 请求

```
DAU = 10,000
人均 600 请求/日（页面状态 500 + 采集 20 + 扫描 15 + 市场 30 + 其他 35）
日请求 = 6,000,000
峰值系数 = 4（20:00–22:00）
峰值 RPS = 6,000,000 / 86,400 × 4 ≈ 278 → 设计 300
```

### 4.2 连接

```
App worker 4 × 8 = 32
pgbouncer default_pool_size = 25（每个 DB）
PG max_connections = 200（含运维/迁移/副本）
```

### 4.3 存储（首年）

| 数据 | 单量 | 规模 |
|---|---|---|
| 玩家域行 | ~30KB/人 | 300MB |
| 账本 | 50 笔/日 × 365 × 0.2KB | ~36GB（分区 + 归档） |
| 行星缓存 | 15–25GB | 可淘汰 |
| 行星改造 | 60 行/活跃玩家 | < 1GB |
| 日志/审计 | — | 10GB/月（90 天） |

### 4.4 规格

| 组件 | 规格 | 备注 |
|---|---|---|
| PG 主 | 4C16G / 200GB SSD | `shared_buffers=4GB` |
| PG 副本 | 同规格 | 排行/报表 |
| App | 2 × 2C4G | 可扩 |
| Redis | 1C2G | `allkeys-lru` |
| pgbouncer | 0.5C | 与 App 同机亦可 |

### 4.5 成本（量级）

| 项 | 月成本 |
|---|---|
| 计算（App/worker/beat） | $80–150 |
| PG 主+副本 | $300–500 |
| Redis | $20–40 |
| 对象存储（备份） | $10–30 |
| 合计（单区） | ~$450–700 |

## 5. 降级目标

| 依赖不可用 | 目标行为 | 可接受影响 |
|---|---|---|
| Redis | 限流降级、缓存直查 | 延迟 +20ms |
| Celery | 行情惰性生成、过期按请求校验 | 榜单延迟 |
| 主库 | 写 503、读走副本 | 只读模式 |
| 下游服务 | 熔断 + 缓存/空值 | 局部不可用 |
| 行星缓存 PG | 直接生成 | 首次访问慢 |
