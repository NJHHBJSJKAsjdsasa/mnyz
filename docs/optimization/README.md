# 优化路线（2026-11）

> 本目录回答一个问题：**项目已经能跑、功能也基本齐了，接下来怎么让它更可靠、更省事。**
>
> 与 [`../TASK-BACKLOG.md`](../TASK-BACKLOG.md) 的分工：
> - TASK-BACKLOG 管 **「还缺什么功能」**（T-xx 编号，逐条勾选）；
> - 本目录管 **「已有的东西怎么变结实」**——一致性、可维护性、交付流程、性能与可观测性。
>
> 全部条目**不含新玩法**，也不改经济规则本身。

## 2. 优先级矩阵

| # | 主题 | 现在不做会怎样 | 投入 | 收益 | 分册 |
|---|---|---|---|---|---|
| **P0-1** | 文档事实自动化 | 每次加迁移都要手工改 4 个文件，必错 | 0.5–1 天 | 消灭整类漂移 | [01](01-doc-sync.md) |
| **P0-2** | 前端闸门进 CI | 闸门只在本地跑，等于没有 | 0.5 天 | 防回退 | [04](04-delivery.md) |
| **P1-1** | 死代码与重复件清理 | 91k 行里混着零引用文件，改哪里都不敢动 | 1–2 天 | 降低改动风险 | [02](02-frontend.md) |
| **P1-2** | 7 条跨模块越界清零 | 别人改表结构会静默打断你 | 2–3 天 | 边界真正生效 | [03](03-backend.md) |
| **P1-3** | 定时任务可靠性 | 34 个 job 里挂一个，没人知道 | 1–2 天 | 经济系统不哑火 | [03](03-backend.md) |
| **P2-1** | 单入口前端（去 5 文档） | 每次跳转拉整页 HTML + 双份数据岛解析 | 3–5 天 | 首屏与体验 | [02](02-frontend.md) |
| **P2-2** | 覆盖率基线与关键路径断言 | 323 个测试不知道护住了什么 | 2 天 + 持续 | 敢重构 | [04](04-delivery.md) |
| **P2-3** | 构建产物策略 | `dist` 入库 → 每次构建 176 文件 diff | 1 天 | 提交历史可读 | [04](04-delivery.md) |
| **P3** | 真实多库 / 真实 LLM | 2PC 与 AI 决策都停在单机可验证阶段 | 各 5 天 | 能力上限 | [03](03-backend.md) |

**建议顺序**：`P0-1 → P0-2 → P1-1 → P1-2 → P1-3`，做完这五项再谈 P2。
理由：前两项把「手工核对」变成机器活，后面所有改动都受益；P1 三项都是**降低未来改动成本**，越早越省。
